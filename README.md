# What was the problem you were solving in the projects for this course?

The ultimate goal in this course was to understand Data Structures and how we could utilize them. This led to our two final projects. The first included writing pseudocode for the three data structures we worked with throughout the course, Vectors, Hash Tables, and Binary Search Trees, and the second had us pick which Data Structure we would use for a Computer Science Course Planning application. This application involved reading course data from a CSV file and displaying it in alphanumeric order. The application would need to have an interactive and simple set of functions to do this: one function to load the file, another to display the courses, and another option to allow you to type in a course number and learn more information about it.


# How did you approach the problem? Consider why data structures are important to understand.

My approach all started with the pseudocode. When working with the pseudocode, I got more familiar with the strengths and weaknesses of each data structure in regard to storing and searching for courses, which was our ultimate goal. In the end, I chose the Hash Table. The Hash Table was not only the fastest of the three but also very suitable for storing and searching at a high frequency. I initially thought of using BSTs, as they seemed to be the best of both worlds when comparing Vectors and Hash Tables, but Hash Tables were just more efficient for this type of program. Understanding Data Structures is key as it allows you to make the correct design choices for different types of programs. This is essential because data structures can easily affect the performance of programs, and depending on the data we are handling, they can help with other functions as well. With the pseudocode, I visualized several components such as loading, displaying, and most importantly searching, and how each would work. I made sure to maintain modularity as well as proper structure. This all helped me, alongside other assignments, to choose the correct data structure.


# How did you overcome any roadblocks you encountered while going through the activities or project?

While working with the pseudocode, I almost treated it as if it were the code I’d run in the program. This is why my pseudocode is very code-like. This approach helped me understand future challenges that would come up, specifically collision handling for the Hash Table and how handling the required data would work. That being said, just because my pseudocode is code-like doesn’t mean that the compiler would understand it or my vision, so I had to make several changes to the code itself for it to actually work. Also, while running the code, I realized that additional handling of cases and input was needed, both for the searches and overall functionality of the program. Simple stuff like pressing option 2 before option 1 or managing all characters, no matter if they were lowercase or uppercase, was essential. Not to mention the infinite loops I had to deal with due to improper management. All of this had to be addressed. That being said, I did my very best to preserve the structure and intent of my pseudocode in my final project, and overall, I believe I was able to do that well.
